# systems/cronlite：迷你 cron 调度器（纯标准库）

不依赖 APScheduler/crontab，手写两个核心件：

## [cron.py](cron.py) —— 表达式解析与下次触发计算

- 标准 5 字段：`分 时 日 月 周`，支持 `*`、`*/步进`、`a-b`、`a,b,c`、`a-b/n`；
- **POSIX 双受限 OR 语义**：「日」与「周」都不是 `*` 时，命中任一即触发
  （`0 0 13 * fri` = 每月 13 日或每周五）——这是 cron 最著名的语义陷阱；
- `next_after(dt)`：非逐分钟扫描，按 月→日→时→分 逐级快进，
  4 年搜索窗口内秒级返回；正确处理闰年（`0 0 29 2 *`）。

## [scheduler.py](scheduler.py) —— 调度引擎

- 后台线程按「最早触发时间」睡眠等待，任务在 `run_once` 中执行；
- **时间与睡眠均可注入**（`clock`/`sleep` 参数）——测试无需真实等待；
- 任务异常被捕获隔离（一个任务炸掉不影响其他任务与调度循环）；
- 每个任务记录 `runs` / `last_result` / `next_run`，可观测。

## 测试（14 项，全部离线）

```bash
pytest tests/test_cronlite.py -q
```

覆盖：解析错误清单、字段边界、`next_after` 跨日/跨月/闰年、双受限 OR 语义、
调度器到期触发/不重复触发/顺延正确性/失败隔离。

## 已知边界

- `next_after` 按天跳变扫描，最坏情况约一年迭代量级，每次调用毫秒级；
- 不支持秒级精度与夏令时语义（中国无夏令时，实际影响有限）；
- 任务在调度线程内执行，长任务应自行投递到线程池（防止阻塞轮询）。
